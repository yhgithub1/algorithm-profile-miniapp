# algorithm-profile-miniapp

微信小程序创新大赛项目：**算法侧写 / 数字人格**。

> 同一个你，在美团、抖音、小红书和淘宝眼里，可能是四个不同的人。

## 当前主体验

```text
美团 / 抖音 / 小红书 / 淘宝
              ↓
        回答生活化问题
              ↓
      生成单个平台画像
              ↓
    看平台可能怎样理解你
              ↓
      跨平台合并数字分身
```

第一版不会读取任何第三方 App 账号。用户只根据自己的真实生活习惯和对推荐页的观察进行填写。

## 四个平台

### 🥡 美团

- 平时自己做饭还是点外卖
- 一周点几次
- 一顿通常多少钱
- 最常吃什么
- 固定几家还是经常尝新
- 是否主动找红包 / 满减 / 神券

主要形成：外卖依赖、客单预算、优惠敏感、餐厅探索、时效偏好。

### 🎵 抖音

- 推荐页最常是什么内容
- 感兴趣的视频会看到什么程度
- 会不会主动搜索
- 会不会点赞 / 收藏 / 评论 / 分享
- 是否追热点

主要形成：观看深度、内容主动性、兴趣跨度、热点敏感、互动表达。

### 📕 小红书

- 首页最常是什么内容
- 买、吃、玩之前会不会先搜攻略
- 会不会收藏并反复查看
- 会不会评论、分享或自己发笔记
- 被种草后会直接行动还是继续查证

主要形成：主动搜索、决策规划、生活探索、表达分享、种草响应。

### 🛒 淘宝

- 买东西前会不会做功课
- 是否等 618 / 双 11 / 领券
- 品牌还是性价比优先
- 收藏后再买还是即时购买
- 是否喜欢新品

主要形成：价格敏感、购买研究、即时购买、品牌倾向、新品兴趣。

## 跨平台数字分身

四个平台会把少量局部行为映射到统一的跨平台维度：

1. 价格敏感
2. 探索倾向
3. 计划性
4. 深挖倾向
5. 社交表达
6. 经典偏好
7. 便利优先

完成两个以上 App 后，`pages/merge` 会开始展示：

- 四个平台分别认识了用户的哪一面
- 哪些倾向在不同 App 中重复出现
- 合并后形成的“数字分身”
- 为什么生活碎片组合后会显得越来越完整

## 当前页面

```text
pages/index             首页
pages/platforms         美团 / 抖音 / 小红书 / 淘宝入口
pages/survey            生活化问答
pages/platform-result   单平台算法画像
pages/merge             跨平台数字分身

pages/select            高级算法实验室：线索选择
pages/profile           动态推断图谱 + 数字人格 + 用户纠错
pages/impact            推荐 / 广告 / 优惠仿真
pages/match             双人圈子融合实验
pages/share             数字人格分享卡
```

## 产品边界

- 不登录或读取美团、抖音、小红书、淘宝真实账号
- 不保存 Cookie、Token、登录态或设备指纹
- 不声称知道这些平台的真实内部算法
- 不暗示这些平台之间实际共享用户数据
- 所有结果统一使用“可能 / 模拟 / 倾向”表达
- 跨平台合并只使用用户主动填写的信息
- 不推断健康、宗教、政治立场等高敏感属性

## 本地运行

1. `git pull`
2. 使用微信开发者工具导入仓库根目录
3. 使用自己的小程序 AppID，或开发者工具支持的测试方式
4. 编译
5. 从首页进入四个 App 的主体验

更详细的技术说明见 `docs/DEVELOPMENT.md`。
