# algorithm-profile-miniapp

微信小程序创新大赛项目：**算法侧写 / 数字人格**。

> 同一个你，在不同 App 的算法眼里，可能是完全不同的人。

## 当前主体验

项目已经从“先选抽象兴趣标签”重构为更生活化的入口：

```text
外卖 / 短视频 / 旅游 / 电商 / 音乐影视
                ↓
          回答日常生活问题
                ↓
         单个平台算法画像
                ↓
          平台可能如何影响推荐
                ↓
         跨平台合并数字分身
```

第一版不读取任何第三方 App 账号。用户只根据自己的真实生活习惯和对推荐页的观察进行填写。

## 五个平台场景

### 🥡 外卖平台

示例问题：

- 平时自己做饭还是点外卖
- 每周点几次
- 一顿通常多少钱
- 最常吃什么
- 固定几家还是经常尝新
- 是否会主动找红包 / 满减

可形成：外卖频率、客单预算、优惠敏感、尝新意愿、时效偏好等画像。

### 📱 短视频平台

示例问题：

- 推荐页最常是什么内容
- 感兴趣的视频会看到什么程度
- 会不会主动搜索
- 会不会点赞 / 收藏 / 评论 / 分享
- 是否追热点

可形成：观看深度、内容主动性、兴趣跨度、热点敏感、互动表达等画像。

### ✈️ 旅游平台

示例问题：

- 一年旅行几次
- 常去哪类目的地
- 酒店预算
- 提前多久预订
- 是否多平台比价

可形成：出游频率、住宿预算、计划程度、目的地探索、比价程度等画像。

### 🛒 电商平台

示例问题：

- 买东西前会不会做功课
- 是否等优惠活动
- 品牌还是性价比优先
- 收藏后再买还是即时购买
- 是否喜欢新品

可形成：价格敏感、购买研究、品牌倾向、冲动购买、新品兴趣等画像。

### 🎧 音乐影视平台

示例问题：

- 追新还是更喜欢经典内容
- 会不会反复听 / 重刷
- 如何发现下一首歌 / 下一部剧
- 内容口味是否跨类型
- 会不会讨论和分享

可形成：经典偏好、内容深挖、兴趣跨度、主动发现、文化表达等画像。

## 跨平台数字分身

每个平台只生成自己的局部画像，同时把少量行为映射到统一的跨平台维度：

1. 价格敏感
2. 探索倾向
3. 计划性
4. 深挖倾向
5. 社交表达
6. 经典偏好
7. 便利优先

当用户完成两个以上平台后，`pages/merge` 会将这些分散信号合并，展示：

- 每个平台分别认识了哪一面的用户
- 哪些倾向在多个平台重复出现
- 合并后形成的“数字分身”
- 为什么碎片化数据组合起来会越来越接近生活方式

## 当前页面

```text
pages/index             新首页
pages/platforms         不同 App 入口
pages/survey            生活化问答
pages/platform-result   单平台算法画像
pages/merge             跨平台数字分身

pages/select            高级算法实验室：线索选择
pages/profile           动态推断图谱 + 数字人格 + 用户纠错
pages/impact            推荐 / 广告 / 优惠仿真
pages/match             双人圈子融合实验
pages/share             数字人格分享卡
```

## 产品表达原则

- 不说“我们知道真实平台内部怎么给你打标签”
- 统一使用“可能 / 模拟 / 倾向 / 如果平台相信这张画像”
- 不读取美团、抖音、携程、电商等第三方账号
- 不保存 Cookie、Token、登录态或设备指纹
- 不抓取真实商业平台价格
- 不推断健康、宗教、政治立场等高敏感属性
- 跨平台合并只合并用户主动填写的数据，不暗示真实平台之间存在数据共享

## 推荐比赛演示路径

最容易让观众理解的是：

```text
外卖平台
↓
“我经常点 20～35 元外卖，也会找优惠券”
↓
优惠敏感 / 高频外卖 / 熟店或尝新画像

短视频平台
↓
“首页多是数码和知识，会看完，还会主动搜”
↓
深度观看 / 主动搜索画像

跨平台合并
↓
价格敏感 + 深挖倾向 + 主动探索
↓
一个更完整的数字分身
```

然后再进入高级算法实验室，展示“一条线索如何扩散成更多标签”和用户如何反驳算法。

## 本地运行

1. `git pull`
2. 使用微信开发者工具导入仓库根目录
3. 在 `project.config.json` 中使用自己的 AppID，或使用开发者工具支持的测试方式
4. 编译
5. 主流程从首页进入“看看不同 App 眼中的我”

更详细的技术说明见 `docs/DEVELOPMENT.md`。
