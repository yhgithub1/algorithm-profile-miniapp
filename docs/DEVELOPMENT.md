# 算法侧写｜开发说明

## 1. 设计目标

这个项目的重点不是“猜中用户”，而是把通常不可见的算法画像过程拆成用户能理解、能反驳、能观察后果的链路。

核心原则：

```text
事实输入 != 推断结果
推断结果 != 真实身份
用户反馈可以削弱推断
所有下游结果都能追溯到上游证据
```

## 2. 数据层

### `data/tags.js`

只存用户主动选择的事实线索。

```js
{ id: 'active_search', label: '会主动搜索感兴趣的话题', group: '内容行为' }
```

### `data/rules.js`

每条规则是一跳可解释推断。

```js
{
  from: 'active_search',
  to: 'active_explore',
  weight: 0.94,
  reason: '主动搜索比被动接受推荐更能体现探索主动性'
}
```

### `data/dimensions.js`

数字人格维度只直接读取“事实线索”，避免二次推断被再次当成事实。

```js
active_search: [
  { dimension: 'contentInitiative', delta: 30, reason: '...' },
  { dimension: 'exploration', delta: 20, reason: '...' }
]
```

## 3. 图谱推断

`utils/inference.js` 使用多层队列展开规则图谱。

单条路径：

```text
源节点得分 × 边权重 = 新证据
```

多条独立证据指向同一个节点时使用 noisy-or：

```text
combined = 1 - (1 - oldScore) * (1 - newScore)
```

它的意义是：多个证据可以增强同一个判断，但不会简单相加突破 100%。

第一版最大深度为 3。

## 4. 人物图谱

`utils/profile-graph.js` 把推断结果重新组织成：

- input：用户事实线索
- inference：中间推断节点
- dimension：高层行为维度 / 汇聚节点

页面 `pages/profile` 使用 Canvas 绘制节点与贝塞尔曲线，并按深度逐层播放。

## 5. 数字人格

当前有 8 个轴：

| 维度 | 低端 | 高端 |
| --- | --- | --- |
| 探索度 | 熟悉优先 | 主动探索 |
| 深挖度 | 快速浏览 | 持续深挖 |
| 怀旧度 | 偏重新内容 | 经典内容共鸣 |
| 价格敏感 | 便利优先 | 价格比较 |
| 决策谨慎 | 快速决定 | 比较后决定 |
| 内容主动性 | 推荐驱动 | 主动搜索 |
| 社交表达 | 私人消费 | 讨论互动 |
| 热点敏感 | 稳定兴趣 | 趋势驱动 |

初始值为 50。事实证据通过正负 delta 改变位置。

这些值不是心理学分数，也不声称测量真实人格。

## 6. 用户反驳机制

`utils/feedback.js`：

- 符合：factor 1.05
- 不确定：factor 0.70
- 不符合：factor 0.20

如果用户否定一个中间节点，依赖该节点的后续路径会一起降权。

数字人格不会因为用户否定一个推断就直接跳到相反人格，而是把对应维度向中性值 50 拉回。

## 7. 算法影响仿真

`utils/impact.js` 只做透明的本地公式演示：

- 内容推荐权重
- 广告 / 促销触达权重
- 优惠券分配仿真

基础商品价格固定。画像只影响模拟优惠，不连接任何真实平台。

## 8. 圈子融合度

`utils/match.js` 将双方主动选择的线索转成：

- 圈子重合度
- 行为节奏相似度
- 兴趣互补度
- 综合融合度

同时生成共同话题解释。

这个模块的产品重点不是“神秘匹配百分比”，而是解释：

> 为什么两个人可能聊得来？

## 9. 分享卡

`pages/share` 使用本地 Canvas 生成图片，包含：

- 阶段性数字人格名称
- 最突出的维度
- 用户主动提供的线索
- 模拟性质声明

可以保存到相册，也可以调用微信分享入口。

## 10. 推荐的后续云架构

MVP 先保持纯本地。

产品验证后再拆成：

```text
微信小程序
   ↓
云函数 API
   ├─ 规则版本读取
   ├─ 匿名反馈提交
   ├─ 自愿保存画像
   └─ AI 文案生成
   ↓
云数据库
   ├─ rules
   ├─ rule_versions
   ├─ anonymous_feedback
   └─ saved_profiles
```

### 不建议让大模型承担核心推断

推荐：

```text
规则引擎得到结构化结果
        ↓
大模型负责自然语言解释 / 共同话题生成
```

不要：

```text
原始用户线索
   ↓
大模型自由猜测这个人是谁
```

## 11. 比赛演示顺序

建议控制在 2～3 分钟：

1. 一句话：一个兴趣能被算法扩展成多少关于你的判断？
2. 一键选择“怀旧深潜”预设。
3. 播放人物图谱逐层展开。
4. 展示数字人格。
5. 对一个明显不准确的节点点“不符合”。
6. 观察后续图谱和人格分数变化。
7. 打开算法影响页，展示推荐和优惠仿真同步变化。
8. 打开圈子融合实验。
9. 最后生成“算法眼中的我”分享卡。

## 12. 上线前仍需做的工作

比赛 Demo 与正式上线是两件事。正式提审前建议继续完成：

- 真机兼容测试
- Canvas 不同屏幕尺寸测试
- 小程序隐私保护指引和实际采集字段逐项核对
- 用户协议 / 隐私声明
- 敏感推断规则审查
- 异常输入、空结果、低端机性能测试
- 云开发接入后的权限与数据最小化设计
